# Contact combination implementation

2026-10-29. `contactEvents` is the common route contract for finite X/Y/Z contacts. Each event has `leg`, input `offset`, signed `direction`, actual `box`, expanded `plane` and optional `role`: contact, reversal, climb, ceiling, landing or step. A role never changes Minecraft collision or ladder-carry rules. Only reversal adds the next-input outward row. Events may occur on the final landing-producing input. Compatible duplicate axis contacts merge; conflicting planes/directions reject the fixed skeleton.

`avoidBefore` and `avoidAfter` carry relative positional rows; `avoidOffsets` selects normal-side intervals. Existing signed blockage chains remain independently composable with these contacts and keep per-physical-block H2/V2/combined3 caps. Exact absence of unselected hits is checked by the shared scene. Finite Y contacts use old X/Z; X uses resolved Y/old Z; Z uses resolved Y/new X. Explicit steps require the actual shared step resolver, matching finite top and resulting overlap, rather than pretending an upward step is a normal downward clip.

`contact_combinations(opportunities, max_events=3, limit=1000, ladder_windows=...)` enumerates all compatible axis subsets under an explicit work cap. Normal coupled choices span one input or two consecutive inputs. A declared ladder window admits the full sequence. Independent normal events separated by free inputs remain separate choices, carried in the complete route solve. Size families are interleaved before caps. No reversal-direction or rarity-based route pruning is added.

`contact_profile` replays the complete chosen horizontal/Y contact and ladder/Sneak sequence through the existing Y recurrence and derives the actual landing duration. `generate_contact_profiles` combines opportunities and regenerates profiles. Same-input ceiling/climb can refresh upward carry after the ceiling cancellation; repeated ceiling/climb and the final omitted climb hit are covered. Disconnected occupied intervals can be represented without a fictitious landing, jump or carry reset.

Collision-box route search now includes bounded generated contact profiles, controlled by `maxContactCombinations` (64 inspected subsets per height pair by default, zero disables this additional profile family) and `maxCombinedEvents` (3 by default). Existing single-wall/ceiling families remain available. These are work limits, not exclusions of particular contact classes; bounded enumeration can miss useful combinations. Automatic multiple-region composition is described below. Bounded discovery does not exhaust every mixed strategy.

Verification: 12 contact-combination tests plus 39 existing generator tests passed. Geometry checks cover all single-input horizontal axis subsets with no Y hit, a ceiling hit or a landing, mirrored through both normal signs. All 63 nonempty subsets of X/Y/Z events over two inputs are enumerated. Full ladder-window combinations, free-gap separation, conflicting events, relative retiming, final-input contacts, repeated ceiling/climb carry and actual step acceptance have coverage. Java-enabled non-IPOPT regression discovery passed 187 tests with 26 integration cases skipped; this is not the complete numerical gate.

The geometry-only `xyz-contact-corner.json` cold search accepted a three-input route in about 8.6 seconds with ceiling plus Z clipping on input 0 and X clipping on input 1. The saved result in experiments/contact-combinations/corner-result.json retains full shared-scene acceptance. This is a witness for the coupled two-input case, not a global-optimality statement.

## Multiple ladders and complete ladder sequences

`compose_ladder_episodes` composes multiple occupied episodes inside one flight and regenerates Y from the original state. It creates one common Sneak/Y timeline, separate region masks and the complete union of actual horizontal hits. Only the real launch receives a jump impulse. Shared route compilation also accepts multiple ladder transitions separated by actual landings. `compose_ladder_contacts` adds arbitrary compatible contacts to an existing ladder schedule and rederives duration/carry, retaining stop/Sneak effects. The generator accepts `contactVariants` and entry-specific `contactEvents`; unprobed transfer windows use `firstCandidateState`, never a fabricated validated-entry claim.

Automatic ladder search now retains a time-prioritized prefix queue and reoptimizes selected complete prefixes when appending ladder transitions. Airborne transfer programs join distinct regions inside a single transition and are checked jointly. Prefix position/velocity is never frozen. `maxInteractions` now defaults to 12, independently of the support/jump count. Work controls include `maxContactVariants=16`, `maxMixedContacts=3`, `maxTransferPrograms=16`, `maxTransferWindows=4`, the existing path/run/skeleton/ranking limits and scene `maxPrefixes`. Zero disables the extra contact/transfer work families where allowed. Transfer entry generation reports its bounded horizon, clipped horizon, generation counters and unprobed status. Automatic airborne templates currently join two region episodes per transfer expansion; the common episode contract itself admits longer sequences. Work limits can miss valid candidates and never establish infeasibility.

Face-connected ladder voxels form one region, including uneven heights. Exact disjoint volumes/cross-sections retain holes and exclude diagonal-only connectivity. Fixed `corridorChoices` select exact occupied rectangles for irregular slices; `faceCorridorChoices` select finite coplanar wall intervals. Automatic generation currently uses default corridor choices rather than exhaustively enumerating these discrete geometry alternatives. Coplanar adjacent wall parts can share a climb face through explicit actual-box alternatives, with exact stage overlap checked independently. No fictitious bounding-box solid or occupancy is accepted.

Contact-plus-avoidance permits the exact touching state of an explicitly selected contact. Other states retain the chosen clearance. This applies consistently during passage generation, reach checks and row compilation, including climbing; adding an avoidance passage must not contradict the selected hit merely because it ends on the face.

Route-specific rarity/reversal/continuation pruning remains deferred. The new work adds representation and bounded enumeration, not a claim that every possible schedule has been searched. Diagonal-only continuous adjacency, switching climb planes within an episode, same-region re-entry, extra initial resume history and general automatic contact-selected step discovery remain outside the automatic family. Existing selected step profiles can compose with contacts, and the shared scene checks the actual step alternatives.


For a normal two-input window, the full axis family has at most six contacts (one per X/Y/Z axis per input) and four horizontal hits. `contact_combinations(..., max_events=6)` enumerates all 63 nonempty subsets when those six primitive opportunities are supplied. To enable that depth in scene generation, set `maxCombinedEvents: 6` and at least `maxWallHits: 4`, plus a sufficient `maxContactCombinations` work budget. Defaults are small work budgets rather than a blacklist of rare patterns. `maxWallHits: 0` now suppresses generated normal horizontal contacts as well as legacy reversal search. Climbing hit runs remain independent of that normal-contact cap.


## Final type-support verification, 2026-10-29

Feature commits are `39d4ede` (common signed contacts) and `a8b659c` (multiple ladder episodes, mixed schedules, finite unions and step diagnostics). The full Java/IPOPT orchestration gate passed **200 tests in 554.373 seconds** with both runtime variables set and no skips. A final focused run passed **23 tests in 4.284 seconds**, including the automatic airborne-transfer snapshot/hash and the step/ceiling/X/Z numerical cases. The unchanged standalone numerical suite passed **51 tests in 28.846 seconds**. Native core completed **799 tests, 33 skipped**, with only the three previously recorded failures in CrossJvmDeterminismTest, InertiaFoldingTest and CostateSmoothingScaleTest. StaticScene's updated step diagnostics test and new simultaneous step-contact test pass.

The first broad run found an ordinary-prefix pool ordering regression and a legacy test selecting the newly introduced general-contact family instead of its dedicated reversal family. Both were corrected; the final full gate includes the fixes. Native step clip-list expectations were updated to the newly retained actual step-path contacts, with no change to movement arithmetic. No acceptance tolerance was relaxed.

The type-support milestone is complete to the explicit search-family limits described above. Route-specific pruning/rarity heuristics remain deferred. Future work should improve bounded enumeration/continuation ranking and irregular-corridor choice coverage without deleting contact families or treating unknowns as infeasible. Final actual-world replay and executable angle/TAS acceptance remain with the other layer.
