## Corridor diagnostics and future-test review

Corridor checking remains enabled. Whether to keep it long term is undecided. The [bug-fix plan](CORRIDOR_CONSTRAINT_FIX_PLAN.md) separates completed instrumentation from pending behavior changes. The [Real11 exact audit](experiments/linkcraft11-opening/audit/CORRIDOR_FAILURES.md) contains a worked failure and diagram.

Rejected returned candidates persist diagnostics at `result.contactAttempts[i].candidateFilter.corridorAudit`; experiment reports may nest the result under a run or evaluation. Record version1 contains:

- `corridorHash`, `corridor` and `gates`: the selected cells, source/helper points, projected rectangles and expected route signature. These permit later identification of artificial route restrictions.
- `failure`: either the first failing zero-based input, Y/X/Z phase, exact segment endpoints/state references and coverage tolerance, or the expected/actual crossing token and crossing sequence. State t is pre-input; input t produces state t+1.
- `scope`: horizon, partial-signature mode and the actual projection scope. Currently `modeledInteractionScope=unspecified` explicitly exposes the missing scope contract. `partialSignature=true` does not switch off future obstacle projection checks.
- `plan`, `candidate`, `vertical`: supplied compiled walls/contacts, returned trajectory/facings/velocity/friction, and the scalar vertical model needed for independent scene replay.
- `selectedPassages`, `selectedHits`, `extraRows`, `numericalRequests`: the selected discrete geometry branch and its numerical problem hashes/status/allocation. `repairAlternatives` records proposed additional rows, not rows already supplied to this solve.
- `physicalReplay`: `not_run` means the corridor rejected the candidate before shared scene validation; `not_configured` means there was no supplied scene. Neither means the trajectory physically passed or failed.

These records describe final returned branch candidates. The adapter's `corridorAudits`, `corridorProjectionRejections` and `corridorSignatureRejections` also count intermediate callback audits. Use `numericalRequests` and worker counters to count solver requests rather than treating every audit as a new call. Existing accepted corridor verdicts and subsequent `geometryCheck` records remain available through the normal per-branch logs. Logging adds no solver/replay calls and does not change the current rejection or repair policy.

To investigate a rejected record, retain the experiment's original fixture/declared scene and replay the saved data with the existing bridge, separately from the timed search:

```python
from standalone.autonomy.block_search import prepare_scene
from standalone.autonomy.obstacle_geometry import check_geometry

scene = prepare_scene(fixture['request'])
physical = check_geometry(scene['collisionScene'], audit['plan'], audit['candidate'],
                          audit['vertical'], compiler, 3)
```

Here `audit` is the saved corridorAudit, and `compiler` is an existing JavaCompiler opened with the standalone compiler manifest. Save the resulting verdict separately. Classify the evidence as route-only rejection with passing physical replay, physical collision from missing constraints, numerical/model discrepancy, or deliberately omitted future interaction in a preliminary model. Preserve failed traces as well as accepted witnesses. In particular, a skipped scene check cannot support an assertion of physical collision. Compare route-only rejects against retained alternatives before deciding whether the corridor policy helps or overrestricts the solve.

## Implemented orchestrator workflow, 2026-11-02

This status supersedes the historical pending descriptions above. The seven-workstream implementation and measured limits are in [the results](experiments/orchestrator-fixes/README.md).

1. Prepare the supplied geometry and original state with the existing scene/compiler bridge. The cells guide spatial routes; their seams and helper-point coordinates are not solver walls. Keep scene coverage explicit.
2. Compose a discrete program with the existing normal/stepping/ceiling builders. Keep all facings free; use zero inertia thresholds while carrying normal momentum. Actual contact rows retain their original pre-input Y/X/Z indices.
3. `evaluate_program(..., scope={purpose: preliminary, modeledBlocks: [...], through: n})` explicitly scopes guidance. In Python use quoted string keys/values. Default complete scope includes every declared solid and the full program horizon. Preliminary guidance cannot become a final incumbent. Omitted future blocks are excluded from scoped projection/signature/readiness/physical acceptance; a separate full-scene replay may correctly fail.
4. Compile coefficients once for reach envelopes. `interaction_reachability` answers only ruledOut or not_ruled_out. Required interaction excluded means reject that candidate; unwanted contact excluded means omit its avoidance; unreachable side/timing means discard that alternative. Never remove mandatory landing rows merely because additional side avoidance is irrelevant.
5. `ConstraintVariants` selects complete existing passage/avoid rows before each complete IPOPT call. Its saved state contains the deterministic reference, pending branch/cursors, seen effective-row keys, emitted count, duplicate count and screened row hashes/proofs. Whole-obstacle exclusions include phase-specific bounds. A soft reference orders choices; it cannot exclude them.
6. Inspect `solveScope`, `solveIdentity`, `best.validationScope`, full-scene acceptance and `repairState.attemptLog/contactLog`. Corridor diagnostics remain under `candidateFilter.corridorAudit`, now with explicit modeled scope. A skipped physical replay is still neither a passing nor failing physical check.
7. Comparison records save same-witness position/velocity, forward velocity, horizontal speed and ordered ground/jump/air history. Only matching schedules/phases/scopes use absolute-clock state for pruning. Missing data and different schedules remain incomparable. Retention records distinguish markedly_worse from saved deferred work.
8. Save `result.searchState`, not just retained parents. The fixed-clock CLI writes this atomically at numerical transitions and supports `--resume`. Ordinary resume restores pending/in-flight work without retrying every numerical unknown; add `--retry-unknown` deliberately. Exact completed outcomes require matching physical/context identities. Legacy parent-only reconstruction is explicitly labelled and is not exact continuation.
9. Outgoing terminal repair work belongs to that exact program, including its objective/horizon. Longer children keep useful facing guesses but do not duplicate incompatible exact old-problem queues. Parent progress remains in the saved records. IPOPT internal iterations/Hessian are not serialized.
10. Dead-prefix proof requires outstanding mandatory contacts and complete exclusion of all possible first interactions in its supported scope. Current implemented proof covers airborne descent below all possible first floors. Grounded/rising or potentially recoverable continuations remain unknown. No implicit B7 landing is added for a fixed-clock airborne goal.

The optional LP screen uses a circumscribed16-face acceleration polygon, coupled p/v equations and outward numerical tolerances. Only numerical infeasibility excludes. It is not a certified rational proof or a change to IPOPT physics. Cold Real11 still spends substantial work on late self-hop/timing histories; its complete discovery and broader false-pruning audits remain open. Preserve the saved frontier and measure those cases rather than widening arbitrary caps.
