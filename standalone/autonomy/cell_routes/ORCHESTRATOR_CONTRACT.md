# Fixed-decision continuous-solve contract

User ruling, 2026-11-01: the continuous solver interface and model remain as before. The orchestrator selects movement inputs and geometric constraints within a spatial route before calling IPOPT. IPOPT optimizes continuous facings for that selected branch. Cell membership, portal timing, movement modes and obstacle interactions do not become new decision variables inside IPOPT.

The orchestrator owns the spatial route and the selected run/jump/step/ceiling/landing decisions, obstacle avoidance constraints and their input/state indices. It compiles those choices into the existing per-tick coefficients, walls and contacts. Facings remain variable throughout the original-state solve. Stored facing sequences are initial guesses; stored intermediate X/Z positions and velocities must not become fixed starting states.

A model-feasible numerical result should satisfy the selected physical route, apart from the explicitly allowed numerical/physics approximations. An unintended collision or corridor rejection means the orchestrator's selected constraints were incomplete or inconsistent. Physical replay remains an independent check of the compiler/selection contract. An IPOPT failure to find a model-feasible candidate remains unknown unless another mechanism proves that fixed branch impossible.

The current cell-route pilot still discovers some missing geometry constraints through lazy validation/repair. That is an incomplete orchestrator implementation, not the target solve contract. Repair-coverage and state-retention fixes do not establish that every pilot call already contains all relevant constraints. The remaining route work is selecting and compiling complete fixed geometric branches before numerical calls. It does not require changing IPOPT or adding discrete routing variables to it.

The two newly corrected bugs are entirely in orchestration. Axis-movement corridor guards now cover connected adjacent rectangles instead of requiring one original rectangle. Pending/unresolved repair branches, constraints and facing guesses are stored as versioned JSON state. Compatible continuations resume them; changed physical context causes a fresh search, and every resumed candidate is revalidated. A changed horizon reopens the unrestricted base branch alongside stored conditional alternatives, because earlier feasibility failures are not certificates for the extended problem.
