# Normal ceiling, ladder ceiling and stepping refactor

Approved direction, 2026-10-30. `ceiling` is a movement type in the normal movement domain, including a normal jump launch such as grind. Ceilings inside a ladder are handled separately through `ladder_ceiling` logic owned by `ladder_climb`, reusing shared primitives. `stepping` is a separate type for the six accepted step/corner cases. This is an implementation plan, not a statement that the new types are implemented.

## Target ownership

| Owner | Cases and responsibility |
| --- | --- |
| `normal` | Ordinary jump, run-off, run and unaffected air intervals |
| `ceiling` | Ordinary normal-air ceiling hit and grind; supports grounded normal launch or an already-airborne normal interval |
| `stepping` | Normal stepping, slab/stair boost, blip, blip-up, corner jump cancel, corner blip-up |
| `ladder_climb` | Existing climb/stops, with internal `ladder_ceiling` event scheduling and replay |
| `ladder_fall` | Existing falling/Sneak behavior; inherited ladder-local contacts remain valid, without a nested normal `ceiling` unit |

Normal-air approach/transfer/final intervals around ladder episodes can contain `ceiling` units. Ladder-owned inputs do not. In particular, the entry-producing input can belong to climbing even if it begins outside the ladder; its helper receives the actual pre/post membership masks. Do not classify ownership using only a global time range or only pre-input membership.

The ladder ceiling policy is called from ladder scheduling, principally climb generation, not from the normal ceiling type. Existing contacts during ladder-owned entry, endpoint stops or an unusual positive-carry fall interval still replay through ladder-local logic. A descending fall does not acquire a new normal-air ceiling type merely to preserve those events. Rarity is not permission to discard currently accepted combinations.

## Current coupling to remove

- `block_search.build_transition_graph` calls `stair_jump_profile` and `ceiling_profile` directly, with separate caches/branches. It then uses the normal generator to wrap every non-stair profile, including ceiling profiles.
- `contact_profiles.contact_opportunities` and `movement_contacts.contact_variants` generate generic upward Y opportunities alongside wall opportunities. Without explicit ownership, the same ceiling event can be generated by both a type and the generic mixer.
- `movement_contacts.contact_variants` imports `ceiling_sequence` from `mixed_ladder`; `movement_entry.entry_contact_options` uses that ladder module for an ordinary airborne approach. The dependency direction is wrong for shared primitives.
- `contact_profiles` imports the generic scalar replay function through `ladder_schedules.trace_ladder_schedule`, despite using it for normal contacts too.
- `movement_program` reconstructs ladder segments and fills other intervals with `normal`. That would erase ceiling/stepping identity in a mixed program. `validate_ladder_events` also participates in constructing the whole per-leg program.
- `shifted_unit` does not currently retime `jumpInputs`; the new profiles need one complete anchor-retiming contract.
- The route adapter derives controls from legacy `profileKind` values (`stair`, `step`, `ceiling`, `contacts`). New case controls must be explicit rather than depending on those labels.

## Shared candidate contract

Use a common movement-choice result containing:

- Typed `units` with `type`, named `case`, input interval `[start,end)` and owner/region where relevant.
- Explicit jump/run/Sneak inputs and relative position/input anchors, including L, H, J and the jump input. Input t still produces position t+1.
- Scalar Y/VY and ground-state history, with entry/exit scalar state and optional physical support. A grounded result does not require a support at the same Y.
- Finite scene contacts, before/after/avoidance constraints and case-specific geometry conditions. Every ceiling event has one owner.
- An open or supported terminal condition. Blip-up and corner blip-up can finish grounded but unsupported and then hand off to normal jump/run-off.

Keep the generated typed program authoritative through composition. Compile/check its controls and masks against its scalar profile, rather than overwriting its non-ladder intervals as normal. Legacy saved profiles get a compatibility adapter that supplies these fields without changing their existing control/physics meaning.

Full X/Z positions and velocities are solved jointly from the original route state. The candidate contract must not store a previous optimizer endpoint as a new fixed initial condition. Y state may be derived from the chosen discrete history through the existing shared simulation.

## Commit 1: extract neutral primitives, preserving behavior

Introduce `vertical_profiles.py` for the generic scalar timeline replay and outcome-profile helpers. Move the reusable replay implementation from `ladder_schedules`; keep `trace_ladder_schedule` as a compatibility wrapper/re-export. `contact_profiles` then depends on the neutral module, not a ladder scheduler.

Introduce `ceiling_primitives.py` for finite ceiling geometry, feet-plane calculation, relative event construction, shared before/after constraints and scalar ceiling prediction/replay hooks. The shared scalar primitives continue to own gravity, thresholds, caps and carry. Do not copy equations into each movement generator.

Move the common parts of `mixed_ladder.ceiling_sequence` into this neutral layer. Normal-air prediction supplies normal masks; ladder prediction supplies ladder/H-hit/Sneak masks. Keep an old import wrapper only for compatibility during migration.

Gate: existing emitted physical schedules and Y/VY/ground/contact histories remain equivalent. Run focused ordinary-ceiling, ladder-ceiling and contact-combination tests. No new profiles or search pruning in this commit.

## Commit 2: make ladder ceiling ownership local

Add `ladder_ceiling.py`. Move ladder-specific ceiling prediction, repeated-contact scheduling and integration with the existing climb/stop choices here. Invoke it through the ladder scheduler/climb generator. It emits internal `ladder_ceiling` events, not top-level `ceiling` units.

Preserve actual ordering: Y ceiling clipping precedes horizontal movement, and an actual horizontal hit ending inside the ladder can refresh climbing carry afterward. Stopping a climb hit changes that outcome. Retain repeated ceiling contacts while pressing a climb wall; do not impose a new single-hit cap or route-specific rarity rule.

Refactor `mixed_ladder`/`mixed_schedule_pool` so they combine ladder-local ceiling options with wall/contact choices. Recompute Y, exit timing and landing after selecting the options. Do not attach ceiling metadata only after accepting an unchanged Y schedule.

At entry/exit seams, dispatch by the owning movement interval and use the real membership masks. A normal approach before the ladder and normal air after leaving it use the normal ceiling generator; entry-producing climb inputs stay ladder-owned. Keep the existing inherited/fall/stop contact replay valid without running the normal `ceiling` type inside a ladder.

Gate: accepted ladder-ceiling routes, repeated ceilings, ceiling plus X/Z contact, endpoint stop plus ceiling, entry/exit seams and full carried-state witnesses remain valid. Assert that no top-level ceiling unit occupies a ladder-owned input.

## Commit 3: authoritative typed composition and retiming

Extend `movement_generation`/`movement_units` with the common choice contract. Add registered type metadata for `ceiling` and `stepping` as each implementation arrives. Preserve ladder occupancy through the ladder types and local events.

Refactor `movement_program`, `validate_ladder_events`, `route.schedule` and episode composition to stitch supplied typed programs and validate their interval partition, masks and contacts. Fill only genuinely unassigned intervals as normal. Preserve ceiling/stepping units in connecting air between ladders; ladder validation validates the ladder portions rather than reconstructing every other type.

Retiming shifts all controls, L/H/J/input anchors, unit intervals, event/avoidance states and contact references exactly once. Add the missing `jumpInputs` coverage. Legacy profiles retain adapters and their public tags; new controls come from the generated profile/program, not tag inference.

Generalize open composition to carry a ground flag independently of physical support. A blip-up output may jump immediately, or use normal run-off from its current height, without adding a fictional landing block.

Gate: mixed-unit identity survives run insertion and multi-ladder composition; all existing controls, contacts and scalar states are preserved; no endpoint pin or momentum reset is introduced.

## Commit 4: pull normal-air ceilings into the ceiling type

Add `ceiling_generation.py`, registering `CeilingGenerator` through the common interface. Move the current `ceiling_profile` strategy here; `ceiling_contacts.py` can remain a legacy import adapter. Support both the existing grounded jump-to-support shortcut and normal-air open intervals with inherited Y/VY, without inserting another jump.

The first migrated case is `ceiling_hit`: propose the impact input and finite ceiling, replay its Y result and carry, and emit the inside-at-impact plus before/after conditions needed for that chosen timing. Ordinary ceiling contact changes Y at the impact; it does not reset X/Z momentum unless an actual retained wall hit requires it.

Use this generator for ordinary support transitions, pre-ladder air, inter-ladder air and final air. Existing `entry_contact_options` calls the normal-air generator for those approach portions. Ladder-owned intervals call only the local handler from commit 2.

Stop graph-wide code from wrapping ceiling candidates as normal. Route ceiling discovery through the registry. Generic contact combination still supports ceiling plus wall events, but receives normal ceiling events from this generator; it must not independently duplicate their discovery.

Gate: ordinary ceiling witnesses and generated approach/final-air ceilings remain accepted; normal ceiling cases are typed ceiling; local ladder ceiling cases remain typed ladder climb.

## Commit 5: pull out the existing stepping cases

Add `stepping_generation.py` and register `SteppingGenerator`. Move/wrap `stair_jump_profile` here, preserving its existing two-input boost and constraints. Add automatic discovery for the existing one-input normal-step contract. Keep compatibility imports in `block_profiles` while callers migrate.

`block_search` asks the registered normal, ceiling and stepping generators for eligible choices instead of embedding their profile-construction logic. Shared graph assembly still handles IDs, caches, queueing and bounds. The ordinary jump remains available beside a step/boost.

Update `compile_block_path` and `floor_checks` to recognize explicit case controls and selected contacts. Ordinary avoidance should not reject the block that the chosen step case intentionally uses. Grounded steps constrain the proper post-state; boost L/H/J controls retain the user definitions and existing support timing.

Move existing height/radius eligibility into type-appropriate handling. Bounds must be sound for all enabled case profiles; the ordinary maximum-jump-height gate cannot run ahead of a valid composite blip/step choice and discard it. This is correctness work, not the deferred aggressive-pruning pass.

Gate: one-input normal step, two-input boost, five-input staircase, run insertion and selected step plus retained wall contacts retain numerical/scalar/scene acceptance.

## Commit 6: add blip and corner stepping profiles

Extend the stepping generator with the four remaining accepted cases:

- `blip`: ordinary lower landing constraint at L, 0 <= higherHeight-yL <= 0.6, higher-block condition at H and air movement into H.
- `blip_up`: yL above the higher level, free next Y below the lower level, yH=yL with grounded output; hand off at H to elevated jump or normal run-off.
- `corner_jump_cancel`: X-facing .42-.6 obstacle, before-J X-face condition and J Z-edge escape using Z-blockage-style successive-state timing; cancelled upward motion and normal jump horizontal movement.
- `corner_blip_up`: lower landing plus X-facing L/H corner conditions using the same Z-blockage timing; blip-up movement/result and continuation.

Reuse one corner-clearance constraint builder for the two corner cases, and common cancel/retained-height Y outcome helpers. Do not turn their avoided X face into a retained wall hit. Z-facing counterparts use ordinary jump or lower landing. Do not add straight-through strategies or the rejected partial-rise 1 -> 1.25 case.

Extend the shared scalar event/profile description only as required for these named outcomes. Extend the standalone scene-acceptance bridge to check named unsupported/elevated outcomes without demanding a nonexistent final support-plane contact. Reuse the current shared resolver; do not implement another Minecraft step algorithm or enumerate its A/B internals as movement types.

Gate: fresh solves for each case, negative timing/height/orientation controls, correct movement coefficients and immediate-jump/no-jump continuations. Existing ladder and normal routes remain accepted.

## Commit 7: add grind under normal ceiling

Add `grind` to `CeilingGenerator`. Require outside-before-J, underneath-on-J, low head clearance, zero jump-tick rise and the specified air recovery. On flat floor the following input lands for the usual two-input cycle; different following geometry hands off to ordinary air/landing as required.

Use the same cancelled-jump Y/control primitive as corner jump cancel, while keeping the geometry distinct. Do not represent grind as an ordinary ceiling impact onto its underside plane, and do not register it as a stepping case. A single occurrence is sufficient.

Gate: grind versus ordinary ceiling-hit distinction, entry timing, head clearance, flat/non-flat following floor, shared cancel-profile equivalence and no unintended wall/sprint cancellation.

## Final acceptance and cleanup

Run the full orchestration suite once the final code is stable. Run numerical/shared-source gates when those implementations change. Include named-case continuous solves from the original state, independent scalar and shared-scene checks, the ladder regression and saved witness revalidation. Game replay/export remains outside this layer.

Keep old imports/format adapters only where still needed by saved contracts/tests; production generation must have a single owner for each case. Add an explicit test that a normal air gap in a ladder route can have a ceiling unit, while the adjacent climb carries only internal ladder_ceiling events. Preserve same/consecutive normal contact combinations and full ladder-window combinations without introducing new rarity pruning.

No cached-generation, dominance pruning, resumable scheduling, fluids or facing-constraint work is included. Time remains the primary ranking key and objective the tie-breaker. Commit every implemented stage independently in the isolated worktree.
