# Decisions

Standing user decisions and the rationale behind them. User instructions override
these docs. What is implemented now is in [current state](CURRENT_STATE.md); work
that is deferred or unapproved is in the [deferred-work register](DEFERRED_WORK.md).
When a decision changes, update this page and current state in the same change;
keep historical measurements tied to their source revision instead of rewriting them.

## Standing decisions

| Topic | Decision and rationale |
| --- | --- |
| Layering | Preserve physical contacts, passages and movement alternatives in the shared DFS. The engine decides in coupled required-anchor spans, optimizes each span against a backward guide objective, and retains recoverable alternatives. Spatial geometry does not set jump timing or constant edge weights. |
| Minimum free width | A passable gap between blocks is at least 0.612 (0.012 beyond the player's 0.6 width), so no player-space free piece narrower than 0.012 exists; such pieces are numerical artifacts and are not kept anywhere (width measured along a tangent axis). Implementation: [generation follow-ups §2](design/GENERATION_FOLLOWUPS.md#2-minimum-free-width-in-the-landing-cover-path). |
| Obstacle geometry | Build one player-space obstacle representation per scene (union of rectangles per height band) and use it wherever geometry becomes avoidance sides, contacts or landing regions; faces shared by solids the player cannot pass between are one side; collision checks stay per box. Implementation: [generation follow-ups §3](design/GENERATION_FOLLOWUPS.md#3-obstacle-footprints-one-player-space-representation). |
| Switch ticks | The objective is unimodal in a switch tick: each family of alternatives that differ only in when they switch obstacle sides is climbed from its first solved point to its ±1 neighbours on optimized solves; IPOPT unknown counts as infeasible; keeping several open until downstream is deferred. Implementation: [generation follow-ups §7](design/GENERATION_FOLLOWUPS.md#7-choose-obstacle-sides-by-optimizing-with-a-switch-tick-climb). |
| Feasibility never chooses | Feasibility checks only prune a branch with no feasible alternative; choosing between alternatives always optimizes. Each anchor leg optimizes its alternatives per movement and keeps the best; up to 2 other alternatives with the same ticks and an objective within 0.3 blocks are kept as fallbacks, restored only when a later leg fails (before slower run-tick arrivals). Decision checks climb every side family and keep the best as an intermediate choice for that search branch, with the exact rows of the stretches settled at the node; each other branch choice's best point and up to 2 close switch timings per choice are held and restored one at a time when the branch below the node dies ([side families](design/AVOIDANCE_PASSAGES.md#side-families-in-search-branches)). |
| Avoidance generation | Geometry-driven passages ([design](design/AVOIDANCE_PASSAGES.md)): one encounter per obstacle cluster (touching solids) per landing segment, sides are maximal free rectangles around it, phase covers from geometry, later domains conditioned on actual earlier rows, one builder for generation and collision repair. In anchor search obstacles are conflict-driven: an obstacle gets passages only once a solve hits it, and one no solve touches is ignored (user, 2026-11-20). No local avoidance, repair, switch-count or retention caps; global run and call budgets keep unfinished work lazy; per-request numerical timeouts remain. Source-era cap fields are read and dropped. |
| Automatic grouping | Consecutive anchor pairs whose encounters touch form one encounter group (user, 2026-11-18): follow touching solids from a pair's end block; solids a landing block can hit join and extend the chain, and the block-table kinds only label them landing or hit/ceiling (user, 2026-11-19) ([O8](design/ANCHOR_POLICY_DECISIONS.md#o8--encounter-groups)). A group is searched as one frame: its anchors stay required and ordered but alternatives are compared only at its end. Anchors are hints, not checkpoints. No authored opportunity/dependency lists or cadence change. |
| Shared geometry | One `SceneGeometry` per scene serves avoidance, landings, ceilings, walls, steps, named cases, grind and unwanted floors. A merged face fixes only its normal axis; its rectangles are alternatives chosen inside `ConstraintVariants`. Landings, steps and flight cases are one choice per merged top face, whose name is the program's `terminalSupport`; anchors, the start and the goal are declared as whole faces (user, 2026-11-21/22). Ceilings and walls merge across touching blocks. |
| Reachability everywhere | Reachability checks screen every generated decision, so a choice the approach cannot reach never becomes a decision. Top and underside contacts are screened per rectangle at generation. |
| Travel check scope | A program appended to a parent checks travel only between its new states and its new states plus the last 10 parent states, not every earlier state (user, 2026-11-21): the parent's pairs were checked when it was built, and measured misses were all within 6 parent states of the end. Implementation: [obstacle relevance](design/OBSTACLE_RELEVANCE.md#cheapest-travel-upper-bound). |
| Progress saves | Resume stays; saving progress during a run is opt-in (`--save-progress` on the solve CLI) because in-run saves took half of a long Real11 solve (user, 2026-11-21). The final report is always saved and resumes like any checkpoint, so only a crash loses work. Caching saved encodings and pruning unread saved state are deferred (C1, C2 in the [deferred-work register](DEFERRED_WORK.md)). |
| Frozen programs | A built program's content never changes; children share it instead of copying it (user, 2026-11-21: safe in the current DFS model). Appends without ladder involvement trace only the new ticks; incremental ladder appends are deferred. Implementation: [generic composition](design/GENERIC_COMPOSITION.md#boundary-and-composition), invariant in [performance](PERFORMANCE.md#cache-and-identity-invariants). |
| Program identity and ties | A program's physics key is a sha256 chain over its states, so a child resumes its parent's chain (`prefixChain`); old keys and checkpoints are not kept (user, 2026-11-21: no backward compatibility). Equal-priority programs are taken in list order, not by key digest, which changes the extended search's order (user: every tied program is expanded eventually, so the fastest order wins). Implementation: [generic composition](design/GENERIC_COMPOSITION.md#boundary-and-composition). |
| Face-based prefilter | Two reachability kinds: face-based (can block B be touched in one flight from launch face F, generous movement, no route) removes blocks before generation; route-based (`InteractionGate.query`) answers for one partial route. The face table measures from every block of the face's owners, with one travel radius per launch block, from the per-tick speed limits 0.7 (jump tick), 0.5 (ground tick) and 0.4 (air tick) as given; a node that ends mid-air uses its launch face. It keeps one set per interaction kind (hit, landing, stepping, ceiling), with heights from the game's jump rise 1.24919 (0.005 inertia threshold) and head reach 3.04919 and no extra margin; blip secondaries are one 0.4-block air tick past a landing block; jumping variants add no reach. Implementation: [obstacle relevance](design/OBSTACLE_RELEVANCE.md). |
| Commitment | When choices become fixed and how alternatives remain open downstream stay deferred ([scope](design/PRUNING_IMPROVEMENTS_BACKLOG.md#commitment-deferred)). Movement cadence, anchor comparison and inter-movement retention remain as selected. Caller-supplied decision windows are removed: grouping is inferred, never supplied. |
| Commitment terms | A **commit** keeps a decision for the rest of the solve and is walked back only on infeasibility, through fallbacks. An **intermediate choice** is a branch decision inside an encounter group that sibling branches can still replace; decision checks make intermediate choices (user, 2026-11-19). |
| Settled stretches | A decision check settles how a branch passes each obstacle on its closed stretches, and the chosen rows carry into every later solve. A re-solve that hits an obstacle on a settled stretch gets the ordinary obstacle repair at the same node, with the settled rows kept, instead of dying or backtracking: the change to the route is usually small (user, 2026-11-22). |
| Margins | One solver margin and one replay tolerance, both 1e-4 (`schema.SOLVER_MARGIN`, `schema.REPLAY_TOLERANCE`), with no per-scene knob: the solver plans every row that far inside (regions to reach shrink, sides to avoid grow, a planned contact crosses its face) so floating-point error never invalidates the replay, and the replay compares with the tolerance as a second buffer. The Java bridge is legacy and keeps its 1e-7 (user, 2026-11-22). |
| Relevance | One generic block, tick and phase eligibility helper for required and unwanted interactions; no landing or avoid special-case system. Proved impossible means no interaction-derived choices, rows or checks. Unknown retains coverage. |
| Spatial route identity | Support occurrences and 3D passages remain meaningful. Visits name merged top faces (coplanar tops merge when the player-space rectangles touch, i.e. less than a player's width apart; a face is named by its blocks' owners). Anchors, the start and the goal are whole faces: the anchor search rejects one whose top face holds another block (user, 2026-11-22). Once the route leaves a face for another, nothing at the feet touches that face again: no landing, lower landing, or target, higher or corner block of a stepping case. Ceiling hits, grinds and wall contacts may repeat any number of times. Consecutive same-face setup hops stay supported. Revisits are deferred ([plan](design/REVISIT_DISCOVERY_DEFERRED_PLAN.md)). |
| Hard transfer | One hard transfer S to E can follow repeated S to S setup hops, even after latching, for every source anchor; all setup impulses count in J. Direct feasibility anywhere latches that anchor transition to single-jump structure for the whole solve, across changed incoming histories; inside an encounter group each pair latches and is enforced separately. **Declared assumption:** hard jumps between anchors never involve stepping, so flight minima consider ceilings only and unknown shortening ceilings yield zero. This is part of hard policy4 and continuation identity, not a proved fact about all maps. |
| Ordering | Absolute T, then requested grounded J, then R (ordinary) or A (turnaround), as `(T,-J,tickCost,id)` in `search/comparison.py`. Turnaround is a binary test against one approach edge (imaginary diagonal if needed) plus a 0.3-block margin, with a 110 degree guide cue. Each decision selects one whole key; no blended scores or progress key. |
| Run ticks | Outside turnarounds a run tick leaves the player on the same face, so only minimum run ticks are generated (user, 2026-11-19/20), from launch tables and vertical replays: before an advantageous jump (it lands on the next required anchor, hits a ceiling, or is a grind, slab boost or corner jump cancel) while run ticks plus its airtime stay below the decision's fastest jump-now landing N, at most 11 (a flat jump lasts 12 ticks), skipping jumps beaten on both total and airtime, with next counts, beaten candidates and a widened N reserved for when branches die; a run-off onto face B, its walk-off input counted as a run tick, at the fewest run ticks (1 to 11) landing sooner than a jump onto B would, only when a jump-now child lands on B, no reserve; a walking step-up (its step input a run tick) on the first tick, else after one run tick, no reserve. A run-off must leave its launch block by an open face chosen from the landing direction, checked by the generators and the creation screen and carried to the node solve (user, 2026-11-20). A ceiling hit lands in its own child's choice, and so does a grind, slab boost or corner jump cancel (a 2-tick jump: the input after its jump tick is airborne); its earliest screened landing counts as a jump-now landing for N, the run-off bound and the scan, and every advantageous jump beats with its built landing; N bounds run ticks only (user, 2026-11-21). Turnarounds generate and prefer run ticks as before ([O9](design/ANCHOR_POLICY_DECISIONS.md#o9--minimum-run-ticks-for-advantageous-jumps)). |
| Launch-face jumps | At an ordinary decision, a jump landing back on the merged top face it launched from (faces merge across touching coplanar blocks; individual blocks no longer count) is generated only when it naturally fits: the room ahead of the player's validated position on the face it stands on after merging (player-centre regions: merged with coplanar touching blocks, clipped by solids through it), along the guide leg's axis or diagonal, exceeds 0.7 of the natural jump. Otherwise it is held until the decision's other branches die (user, 2026-11-21; [O11](design/ANCHOR_POLICY_DECISIONS.md#o11--jumps-back-onto-the-launch-face-must-fit-it)). Restoring it once run ticks reach its airtime is deferred ([S9](DEFERRED_WORK.md)). |
| Backward moves | An ordinary decision generates no move needing more than 0.3 blocks of travel in a direction its guide leg disallows, and no side entry or wall contact by such a move. Within 22.5° of an axis the leg allows forward and sideways moves, otherwise its two forward axis directions (one knob, shared with O11). Run-off avoidance, which knows its landing, keeps its beyond-on-both-axes test (user, 2026-11-21 and 2026-11-22; [O10](design/ANCHOR_POLICY_DECISIONS.md#o10--no-backward-moves-at-ordinary-decisions)). |
| Comparing alternatives | Compare only at encounter-group ends and the final task; optional movement inside a group is coupled. Slower-arrival deferral at a group end applies only when every pair of the group is latched. Slower compatible hard arrivals are recoverably deferred unless protected by more J OR fewer R (fewer A in a turnaround); raw extra A or R is no protection. Equal time stays live. A strict optimistic full-finish bound `T+max(H,V)>bestT` overrides local protection. Deferrals are not infeasibility proofs. |
| Different schedules | Absolute-tick position and velocity are not comparable across different ground and air histories. Equal counts do not establish equal schedules. Legacy common-clock guards stay in their compatibility context. |
| Coupling and cadence | All decisions between required anchors stay coupled through original-state re-solves with earlier facings free. Solve at every completed meaningful jump or contact decision (cadence 1), never per raw input; anchors and the final solve are mandatory. Cadence 2 or 4 is an open measurement, chosen by wall cost, not call count. |
| Solver boundary | Inputs, events and physical history are fixed before each exact-node query. Only that node can receive an infeasible result; a child failure never marks an untested ancestor. No ancestor-testing pass. An empty, exhausted constraint generator with no remaining repair work is exhausted (a backtrack), not suspended and not infeasible. |
| Intermediate solves | Anchor legs optimize the configured onward objective and the final leg the real objective, over every alternative the climb visits. Decision checks optimize their own decision objective the same way, so side families are compared at the decision point by their best climbed point (user, 2026-11-19). A decision objective aims from where the program ends (the block its last movement landed on, or took off from when it ends airborne) toward the next required anchor's guide point, and past that anchor when the end point is inside its turnaround; the child's creation-time relaxation screen uses the same objective (user, 2026-11-20). `constant_zero` remains an optional API mode, not the default ([feasibility mode](IPOPT_FEASIBILITY_MODE.md)). |
| Disk relaxation | Automatic discovery solves every interim numerical query on the Clarabel disk relaxation (`|a| <= magnitude`; retained states, native equalities, `1e-9` tolerances) and spends IPOPT only where the relaxation may not be close to the full problem. Repair-loop solves and the switch-tick climb stay relaxed; at the loop's end a confirmation walk over each side family's best point (and a close second) re-solves, best first, a candidate whose relaxed optimum leaves more than 10% of a jump tick's acceleration unused by IPOPT in one attempt seeded with the disk directions turned by `1e-4` rad, as the finalization is (no averaging, no absolute floor; every measured full-model infeasibility had a jump tick at least 28% short, and objective gaps alone do not warrant IPOPT, [alarm](../research/disk-relaxation/README.md#alarm-ticks); the seed is a measured assumption to revisit, [seed benchmark](../research/disk-relaxation/README.md#confirmation-seed)), whose outcome governs it; an IPOPT timeout or unknown is infeasible, the walk stops once a confirmed point beats the next relaxed one or after 3 examined candidates with one confirmed, and a check with none confirmed is pruned (user, 2026-11-20). There is no lineage promotion: every request is solved relaxed and decided by its own alarm, so a confirmed gap (above `1e-4` blocks it is reported as material) affects only its own request. The run ends with one IPOPT finalization of the best relaxed finish through the repair loop, falling back to the next-ranked finish; nothing is published if all fail. Inertia thresholds are out of scope. [Execution](ANCHOR_SEARCH_EXECUTION_REFERENCE.md#numerical-backend-and-finalization), [solver](reference/NUMERICAL_SOLVER.md#disk-relaxation). |
| Run budgets | Physical anchor DFS uses the session deadline and global call allowance continuously, with no service-turn or per-program quotas. Work that cannot start inside the budget stays pending. |
| Local guidance | Backward nearest-point guides and a continuous progress objective, optimized on anchor legs and decision checks. Progress is not a discrete key or pruning rule. |
| State protection | Position and velocity protection helpers are inactive for a global peer-exclusion pass; the tick-only policy adds no such dominance claim. A first feasible pose is not a bound on later re-solves. |
| Inertia | Disable thresholds only; keep normal momentum. Exact inertia-pattern work is deferred. |
| Corridors | No automatic raw-walk containment or portal-clock filters. Guide points are soft objective and turn cues. Required physical contacts, passages and full scene validation stay hard. |
| Real11 task | Physical B7 is `[729,0,-1095,730,7,-1093]`; land on actual B7, least T then maximum Z; guide `(729.5,7,-1093)`. No virtual or X<729.7 rows. Anchors B2/B3/B4/B5 are caller-declared for the benchmark; movement choices and optional supports remain search decisions. Required anchors are not a fixture-specific algorithm rule. The maintained case has no first-jump whitelist: producers, screens, comparisons and finish bounds select work. |
| Longer Real11 | [Extended task](../cases/real11/extended-anchors.json): anchors B2/B3/B4/B5/B7/B20, terminal B22. B6 stays physical X[730,731] and B7 unit size; B9's two entries are B9a/B9b; the stair is two blocks, B13a (lower half) and B13b (upper half) ([geometry](REAL11_EXTENDED_GEOMETRY.md)). Trials are paused until the current solver changes settle; resume cold through the [checklist](../research/real11-long-solve/README.md#status-and-resumption). |
| Movement bridge | Search runs without a JVM. The in-process Python bridge is the default for every search entry point; an explicit `--compiler` or `PKC_RUN_TICKS_COMPILER` selects the Java bridge, the flag first. Coefficients are tables generated from the Java compiler, which stays their source of truth; Python owns the finite-scene and footprint checks with the Java bridge as differential oracle. Replies, request hashes and model labels are identical, so checkpoints resume across bridges; a semantic break needs a separate decision on its checkpoint impact. The mod simulator stays authoritative for executable replay. |
| Budget | Minutes or longer are acceptable for accuracy. Explain structural failures before widening caps; preserve unfinished work. |
| Workflow | Persist decisions and measured facts in these docs; plan, handoff and resume notes stay out of the repository. Commit a feature with its tests, docs and fixtures. |
